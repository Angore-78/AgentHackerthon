Integrating PayHero's Lipwa Link & STK Push

A comprehensive, step-by-step developer guide for connecting PayHero's payment infrastructure to your logistics platform for collecting transit fees via M-Pesa.

PayHero Integration Architecture

1 Consignor Checkout

Client initiates payment for shipment delivery fees.

2 Lipwa Link / STK

Dynamic link generated with reference or direct STK push to mobile phone.

3 M-Pesa Settlement

Customer enters PIN and authorizes transaction via Safaricom M-Pesa.

4 Webhook Callback

PayHero notifies endpoint, reconciling shipment as PAID automatically.

1

Create a PayHero Kenya Developer Account

Sign up and obtain your authentication credentials.

1. Navigate to payhero.co.ke and register for a business or developer account.

2. Complete the standard merchant verification and navigate to Settings ➔ API Keys.

3. Generate your API Username and API Password. PayHero uses these credentials for HTTP Basic Authentication.

2

Link your M-Pesa Channel & Configure Lipwa Link Slug

Attach your Safaricom Paybill or Till Number to receive disbursements.

1. In the PayHero Dashboard, go to Channels ➔ Add Channel.

2. Select your channel type: M-Pesa Buy Goods Till or Paybill Number.

3. Once connected, note down your numeric Channel ID (e.g. 133).

4. In Lipwa Links, claim your custom branded link handle (e.g. lipwa.link/transitflow).

3

Constructing Dynamic Lipwa Links with Query Parameters

How TransitFlow generates seamless pre-filled checkout URLs.

Instead of requiring customers to manually type invoice amounts or till numbers, construct a dynamic URL format:

https://lipwa.link/{account_slug}?amount={amount}&phone={phone}&name={name}&channel_id={channel_id}&reference={reference}&success_url={success}&failed_url={failed}
Parameter Type Description
amount Integer / Float The required payment amount in KES (e.g. 3500).
phone String Pre-fills customer's mobile number (e.g. 254712345678).
name String Customer's name displayed on checkout header.
channel_id Integer Directs funds into the specific Till / Paybill.
reference String Unique transaction code (e.g. PAY-TF-98A1) used for automated reconciliation.
success_url URL Where the customer is redirected following successful M-Pesa approval.
4

Programmatic STK Push via PayHero API v2

Directly dispatches the Safaricom PIN prompt to the customer's device.

Endpoint: POST https://backend.payhero.co.ke/api/v2/payments

Headers:

Authorization: Basic <base64_encoded(api_username:api_password)>
Content-Type: application/json

Python / Django Implementation Code:

import requests
import base64

def trigger_payhero_stk(amount, phone_number, channel_id, external_reference, callback_url):
    auth_str = f"{settings.PAYHERO_USERNAME}:{settings.PAYHERO_PASSWORD}"
    b64_auth = base64.b64encode(auth_str.encode()).decode()
    
    payload = {
        "amount": int(amount),
        "phone_number": phone_number,       # Format: 2547XXXXXXXX
        "channel_id": int(channel_id),       # e.g. 133
        "provider": "m-pesa",
        "external_reference": external_reference,
        "callback_url": callback_url
    }
    
    headers = {
        "Authorization": f"Basic {b64_auth}",
        "Content-Type": "application/json"
    }
    
    response = requests.post(
        "https://backend.payhero.co.ke/api/v2/payments",
        json=payload,
        headers=headers,
        timeout=15
    )
    return response.json()
5

Webhook Handling & Real-time Reconciliation

Auto-marks shipment as PAID when PayHero sends payment notifications.

Register your callback URL in TransitFlow settings (e.g. https://yourdomain.com/payments/callback/). PayHero will deliver a POST notification containing:

{
  "status": "Success",
  "external_reference": "PAY-TF-A87BC1",
  "amount": 3500,
  "MpesaReceiptNumber": "QKB8921X3L",
  "phone": "254712345678",
  "channel_id": 133,
  "timestamp": "2026-11-17T07:30:00"
}

TransitFlow matches external_reference with the pending PaymentTransaction, extracts the M-Pesa receipt code, marks the transaction as SUCCESS, and flips Shipment.is_paid = True.

Testing With the Built-In Sandbox Simulator

During local development or evaluation, you do not need real M-Pesa funds. TransitFlow includes a Sandbox Simulator toggle:

  • Whenever a payment is initiated, click "Simulate M-Pesa Payment Success" on the checkout or detail screen.
  • The system generates a realistic Safaricom M-Pesa code (e.g. QKB718942A) and executes the full reconciliation loop immediately.
  • When ready for live deployment, navigate to API Settings and switch the toggle to Live Production.
